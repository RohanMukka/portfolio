### Pillar 1: a demand-driven render pipeline

**A constraint the design has to respect.** There are no particle velocities
to test against ε: the swarm is stateless. Every point's position is a pure
function of its seeds, a dozen uniforms and `uTime` (`particles.ts:370-437`).
So "at rest" has two parts:

1. **Input-driven channels have converged.** These are everything
   `scene.ts:417-468` eases: `chapter`, `progress[6]`, `focus[8]`,
   `pointer.{x,y,on,press}`, `dive`, `spin`/`spinSpeed`, `intro`,
   `layers[4]`. Their residual is cheap to compute exactly.
2. **Ambient time is allowed to stop.** The stream flows, the name
   shimmers, the crystal turns, the grain changes, all on `uTime`. Freezing
   `uTime` mid-shimmer looks broken, so time has to **decelerate**: a
   `timeScale` that decays to 0, with `simTime += dt * timeScale`.

**State machine** (`src/stage/clock.ts`, new):

```
            input / invalidate()                   residual > ε
   ┌──────────────────────────────┐            ┌───────────────┐
   ▼                              │            ▼               │
ACTIVE ──residual ≤ ε──► AMBIENT ──6 s quiet──► DOZING ──timeScale < 0.01──► ASLEEP (no rAF)
   ▲                                              │                             │
   └──────────── any wake source (≤ 1 vsync) ─────┴─────────────────────────────┘

PAUSED   user's "Pause motion" control: timeScale = 0, renders only on scroll/resize
COVERED  case study open, tab hidden, or canvas off-screen: no rAF at all
```

- **Wake sources** call `clock.invalidate(reason)`: `scroll` (Lenis drives
  native scroll, so its glide keeps waking), `pointermove`/`pointerdown`,
  `resize`, theme change, `fonts`, and every write to the stage store.
  `store.ts` gets setters (`setDive`, `setCovered`, `setSpin`…) that call
  `invalidate()`; `CaseStudy.tsx:91,185` and `Labels.tsx:59` stop writing
  `stageState` fields directly.
- **Wake latency**: the handler calls `requestAnimationFrame`, so the first
  frame lands on the next vsync (≤ 16.7 ms at 60 Hz). On wake, `last` is reset
  so `dt` doesn't spike, and `timeScale` ramps 0 → 1 over 250 ms so ambient
  motion picks up rather than jumps. Input-driven channels ease on real `dt`
  and respond at once.
- **ε per channel**: chapter/progress/dive 1e-4, pointer/focus/press 1e-3,
  `|spinSpeed|` 0.01 rad/s plus the face-the-viewer error.

```ts
// src/stage/clock.ts (sketch)
export type Mode = "active" | "ambient" | "dozing" | "asleep" | "paused" | "covered";

export const createClock = (step: (dt: number, simDt: number) => number /* residual */) => {
  let mode: Mode = "active";
  let raf = 0, last = 0, quietSince = 0, timeScale = 1;
  const AMBIENT_MS = 6000;          // how long ambient motion plays after the last input
  const EPS = 1e-4;
  const tick = (now: number) => {
    const dt = Math.min((now - last) / 1000, 0.1);
    last = now;
    if (mode === "dozing") timeScale *= Math.exp(-4 * dt);          // ~0.8 s to stillness
    else if (mode !== "paused") timeScale = Math.min(1, timeScale + dt * 4);
    const residual = step(dt, dt * timeScale);
    if (residual > EPS) { mode = "active"; quietSince = now; }
    else if (mode === "active") mode = "ambient";
    if (mode === "ambient" && now - quietSince > AMBIENT_MS) mode = "dozing";
    if (mode === "dozing" && timeScale < 0.01) { timeScale = 0; mode = "asleep"; raf = 0; return; }
    raf = requestAnimationFrame(tick);
  };
  return {
    invalidate(reason: string) {
      quietSince = performance.now();
      if (mode === "covered") return;
      if (mode !== "paused") mode = "active";
      if (!raf) { last = performance.now(); raf = requestAnimationFrame(tick); }
      stats.wake(reason);           // feeds the X-Ray timeline
    },
    cover(on: boolean) { /* cancel rAF / resume */ },
    pause(on: boolean) { /* PAUSED: timeScale 0, render on invalidate only */ },
    get mode() { return mode; },
  };
};
```

**Fewer passes per frame.** Today's 18 draw calls are: scene 3 (backdrop,
dust, points) + `UnrealBloomPass` 13 (high-pass, 5 mips × 2 separable blurs,
composite, copy) + `OutputPass` 1 + film 1. In `post.ts`, replace them with
a dual-filter (Kawase) bloom at half resolution, 3 down + 3 up, with the
threshold folded into the first downsample, and fold output conversion,
grain, vignette and fringing into one final pass: **3 + 6 + 1 = 10 draws**,
and two full-resolution passes instead of four.

**On BVH and octree bounds: don't draw them.** This scene has no spatial
index. Formations are computed per vertex on the GPU, and picking is done by
DOM buttons placed over projected node positions (`Labels.tsx`). Drawing
"BVH bounds" would be decoration pretending to be instrumentation, which is
exactly what the X-Ray mode is meant to argue against. If CPU picking is
ever wanted (canvas-native node targets), eight bounding spheres is the
honest structure; a BVH buys nothing at n = 8.

**Telemetry.** `src/lib/telemetry.ts` sends web-vitals plus stage metrics
(wake latency, % asleep, adaptive-quality tier reached, renderer bucket) with
`navigator.sendBeacon` to `api/telemetry.ts`. That function checks a fixed
schema and increments log-bucketed histograms in the Upstash Redis the site
already uses for `/api/views`. It stores no IP, sets no cookie, holds no
per-visitor rows. `api/stats.ts` serves p50/p75 for X-Ray and the footer
("Across N visits this week: p75 INP 48 ms, stage asleep 71% of the time" —
illustrative; it will print real numbers).

### Pillar 3: transitions and legibility, with the maths

- **Text safe zones** (`src/stage/safe-zones.ts`, new). Text blocks carry
  `data-stage-safe`; the stage reads their rects when layout changes and
  passes up to six as `uniform vec4 uSafe[6]` in NDC. In the vertex shader,
  after projection:
  `inside = max over k of smoothstep(feather, 0, sdBox(ndc − cₖ, hₖ))`, then
  `vAlpha *= mix(1.0, 0.18, inside)` (disabled during the dive). This fixes
  stops 5 and 7, About's stop under "Hyderabad, 2020.", the tablet
  collisions and the phone More-work list with one mechanism. Target: 0% of
  title pixels under 3:1 at any stop.
- **Hero → About bokeh.** Pass `uTravel = sin(π · fract(chapter))` (already
  computed as `travelling` in `scene.ts:408`). Then `blur *= 1 − 0.75 ·
  uTravel` and the point-size cap goes from 36 px to `mix(36, 10, uTravel)`.
  During travel, `focusDist` follows the swarm centroid
  (`|eye − lerp(place[from], place[to], m)|`) instead of `VIEW_DISTANCE`.
  The hero copy fades over `[0, 0.25]` of the hero's scroll, not
  `[0, 0.45]` (`Hero.tsx:51`).
- **Work → Skills.** Keep the paint, but drive it from the sentence's own
  entry (`offset: ['start 85%', …]`) so words start lighting as they arrive,

### Pillar 5: the load path

- **Prerender the hero shell** at build time (`scripts/prerender.mjs`,
  `react-dom/server`, written into `dist/index.html` with critical CSS
  inline). FCP stops waiting on 161 KB of JS (8.5 s on slow 3G).
- **Self-host fonts** (Inter Tight 800, Latin subset, `<link rel="preload">`)
  instead of the Google Fonts CSS → woff2 chain (14–18 s on slow 3G).
  Self-host the skill icons too (removes the cookie; BP 75 → 100). Add
  `robots.txt`.
- **Name hand-off gated on the first frame.** `createStage` returns
  `firstFrame: Promise<void>`, resolved after the first `lens.render` with
  `uNameCount > 0`. `Stage.tsx` sets `ready` from it, and only then does
  `data-stage-name` cross-fade the HTML name out over 300 ms. Target: no
  sample on the slow-3G film without a name, after the intro.
- **framer-motion** through `LazyMotion` + `domAnimation`.
- **Optional, and the real engineering flex: replace three.js** with a
  ~600-line WebGL2 core. It needs programs, VAOs, framebuffers, float
  textures, `KHR_parallel_shader_compile` and a little matrix maths, which
  is everything this scene uses. That's about 137 KB gz → about 12 KB gz,
  and less parse/compile on throttled phones. Guard it with a parity
  harness: golden frames per chapter, SSIM ≥ 0.98 against the three.js
  renderer. It's the riskiest item here; do it last.
